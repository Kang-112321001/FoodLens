# FoodLens 智慧食品辨識與營養紀錄系統

FoodLens 是 Web 程式設計課程專題，目標是將公開食品資料整理為可搜尋、可比較的網站，協助使用者查看食品營養資訊，並依實際攝取量換算營養數值。

## 學號

112321001

## 專案目的

市售食品雖然通常有營養標示，但不同食品的份量與單位不一致，使用者不容易快速比較。

FoodLens 以相同營養基準呈現相近食品的資料，讓使用者能查詢並比較熱量、糖、脂肪、蛋白質與鈉等資訊。

本系統提供食品資訊參考與飲食紀錄，不提供醫療診斷或營養治療建議。

## 目標使用者

- 想快速查詢包裝食品營養資訊的一般使用者。
- 需要記錄實際食品攝取量與營養數值的使用者。
- 希望比較同類食品熱量、糖、脂肪、蛋白質與鈉含量的使用者。
- 需要控制糖分或鈉攝取，但仍會自行依專業醫療建議判斷的使用者。

## MVP 預計功能

- 食品名稱搜尋。
- 顯示食品營養資訊。
- 同類食品營養比較。
- 輸入實際攝取量，換算營養數值。
- 建立飲食紀錄。

## 技術架構

- 前端：HTML、CSS、JavaScript。
- 後端：Node.js、Express。
- 資料庫：SQLite。
- 資料處理：由 Express API 查詢 SQLite，並以 JSON 回傳前端。

正式食品資料不會整份載入瀏覽器；JSON 僅用於資料匯入、測試與 API 傳輸。

## 資料需求

系統需要保存以下食品資料：

- 食品名稱。
- 食品類別。
- 製造商。
- 食品追溯碼或其他可識別欄位。
- 營養標示基準。
- 每份重量。
- 熱量。
- 蛋白質。
- 脂肪。
- 糖。
- 鈉。
- 資料來源與更新時間。

缺少的營養資料以 `NULL` 保存，不視為 `0`。

## External API

第一階段不直接從瀏覽器呼叫外部 API，而是先下載食藥署公開資料，經過清理後匯入 SQLite。前端再透過 FoodLens 的 Express API 查詢資料。

後續若加入 OCR 或 AI 食品辨識功能，才會串接外部影像辨識 API。相關 API Key 與密鑰不會寫入前端程式。

## Security／Privacy

- API Key、資料庫密碼與憑證不得寫入前端程式或上傳 GitHub。
- 敏感設定使用 `.env` 保存，並由 `.gitignore` 排除。
- 使用者輸入送到後端前必須進行格式與長度驗證。
- 前端不能直接存取 SQLite，必須透過 Express API。
- 第一階段不蒐集醫療診斷或健康病歷資料。
- 後續若加入會員密碼，必須使用雜湊保存，不得儲存明文密碼。
- 顯示食品資料時應避免使用不安全的 HTML 插入方式，降低 XSS 風險。

## 資料處理流程

1. 下載公開資料檔。
2. 檢查資料總筆數與欄位數量。
3. 進行欄位對應與單位解析。
4. 檢查缺值、重複值與異常資料。
5. 保留資料來源、資料更新時間、營養基準、原始標示與缺值狀態。
6. 以追溯碼或其他可識別食品欄位匯入 SQLite。
7. 瀏覽器透過 Express API 查詢 SQLite。
8. Express API 以 JSON 格式回傳查詢結果。
9. 前端 JavaScript 將查詢結果更新到頁面中。

## SQLite 資料庫建置與重建（W6）

### 資料庫架構

FoodLens 使用 SQLite 儲存食品、營養、會員及匯入紀錄。

資料庫包含六張資料表：

| 資料表 | 用途 |
|---|---|
| Foods | 儲存食品基本資訊及追溯碼 |
| FoodNutrition | 儲存不同基準的營養資料 |
| Users | 儲存會員資料 |
| Favorites | 儲存會員收藏 |
| Sessions | 儲存會員登入 Session |
| ImportRuns | 記錄每次資料匯入結果 |

資料庫使用 Primary Key、Foreign Key、UNIQUE、CHECK 及 INDEX 維持資料完整性，並在資料庫連線中啟用外鍵檢查。

### 資料庫初始化

在專案根目錄執行：

```powershell
node scripts/init-db.js
```

程式會讀取 `database/schema.sql`，建立 SQLite 資料表。

資料庫檔案：

```text
database/foodlens.db
```

### 匯入食品資料

首先將官方公開資料解壓縮，確認 CSV 位於：

```text
data/extracted/188_2.csv
```

匯入最多 2,000 筆有效食品：

```powershell
node scripts/import-test-data.js
```

匯入完整資料：

```powershell
node scripts/import-test-data.js --all
```

匯入程式會進行欄位對應、數值解析、單位判斷與無效資料排除，並保存食品及營養原始文字。

使用食品追溯碼進行 Upsert，避免重複新增相同食品。

匯入時使用 SQLite Transaction，發生資料庫操作錯誤時執行 ROLLBACK，避免部分成功資料覆蓋既有可用資料。

每次成功匯入後，會將結果寫入 ImportRuns，並產生：

```text
data/import-report.json
```

### 匯入結果檢查

執行：

```powershell
node scripts/check-import.js
```

可檢查食品資料筆數、營養資料筆數、熱量缺值與孤兒資料。

2026 年 10 月 21 日測試結果：

| 項目 | 筆數 |
|---|---:|
| Foods | 2,000 |
| 每 100 公克營養資料 | 1,776 |
| 每 100 毫升營養資料 | 2 |
| 每份營養資料 | 2,000 |
| 孤兒營養資料 | 0 |

重複匯入時，程式顯示新增食品 0 筆、更新食品 2,000 筆。

### 原始資料品質分析

執行：

```powershell
node scripts/profile-data.js
```

產生品質摘要：

| 項目 | 結果 |
|---|---:|
| 原始資料總筆數 | 50,650 |
| CSV 欄位數量 | 54 |
| 重複追溯碼筆數 | 0 |
| 非數字營養欄位值 | 144,448 |

完整品質報告儲存於：

```text

```

非數字營養欄位值可能包含空值、文字標示及特殊數值格式，不直接代表錯誤食品筆數。

### 資料庫備份與重新建立

重建前先備份現有資料庫：

```powershell
Copy-Item .\database\foodlens.db .\database\foodlens-backup.db
```

如需建立全新資料庫，應先確認備份完成，再將原資料庫移至其他位置，然後執行：

```powershell
node scripts/init-db.js
node scripts/import-test-data.js
node scripts/check-import.js
```

上述流程會建立資料表、匯入測試食品資料並檢查結果。

注意：重新建立資料庫會失去原資料庫中的會員、收藏及飲食相關資料，因此正式使用時應優先採用備份及更新匯入，不直接刪除現有資料庫。

以下檔案不放置於 `public` 目錄，也不提交至 Git：

- SQLite 資料庫及備份。
- 原始 CSV、ZIP 資料。
- TLS 私鑰與憑證。
- `.env` 環境設定。
- 資料品質及匯入報告。

透過 `.gitignore` 排除上述檔案，避免將資料庫及敏感資訊公開。

## 營養比較限制

FoodLens 的比較功能用於協助使用者比較相近食品的營養資訊，不用來判定某項食品絕對較健康。

- 一次最多比較兩項食品。
- 僅允許相同營養基準的資料直接比較。
- 每份、每 100 g、每 100 mL 必須分開處理。
- 優先比較相同類別的食品，例如優格與優格。
- 不將飲料與餅乾直接判定高低。
- 食品重量或密度未知時，系統不會將 g 與 mL 強制換算。
- 缺少的營養欄位以 `NULL` 保存與顯示，不當作 `0`。
- 使用者可輸入實際攝取量，系統依原始營養基準換算估計值。
- 換算結果仍以資料來源與使用者輸入的份量為準。
- 資料品質以公開資料原始內容為準。
- 系統不宣稱提供即時價格、庫存或涵蓋所有通路資訊。

若後續加入 AI 影像辨識或熱量估算，結果只能作為估算範圍，並須顯示資料來源、信心程度與使用限制。
